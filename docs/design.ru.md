# От адреса репозитория до SVG

Для карточки нужны три запроса: сведения о репозитории, последний релиз и
последний запуск workflow. `fetchCard` в `src/card.ts` сначала загружает сам
репозиторий. Релиз и workflow запрашиваются параллельно. Если один из этих двух
запросов завершился ошибкой, соответствующая строка останется unavailable.
Отсутствие релизов при ответе 404 выводится отдельно как none published.

В поле ввода принимаются `owner/repository` и HTTPS-адрес на github.com.
Проверка отклоняет другие хосты, учётные данные в URL, query и fragment.
Токен не нужен: запросы используют публичный API без cookies и referrer.

## Когда фиксируется время

После завершения запросов создаётся capturedAt. Рендерер получает готовую
структуру и только форматирует эту отметку в UTC. Если поменять палитру или
ещё раз скачать карточку, время останется прежним. Дата последнего push
приходит отдельно из GitHub. У демонстрационных данных отметка неприменима.

## Почему текст проходит через escapeXml

SVG разбирается как XML. Описание репозитория может содержать `&`, кавычки или
угловые скобки, поэтому подставлять его прямо в разметку нельзя. Рендерер
экранирует строки и убирает символы, запрещённые XML 1.0. В том числе убираются
одиночные UTF-16-суррогаты; корректные пары, например emoji, сохраняются.

В `test/card.test.ts` есть описания с похожим на HTML текстом, управляющими
символами и повреждённым Unicode. Тесты также проверяют обе палитры и неизменность
времени при повторном рендеринге. Правила символов: [XML 1.0](https://www.w3.org/TR/xml/#charsets).

Готовый SVG содержит текст и простые фигуры без внешних картинок, скриптов
и шрифтов. Последний workflow относится к одному запуску. Скачанную карточку
нужно заново сформировать, если нужны новые метаданные.
